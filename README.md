# 四边扫描去黑边

这是一个完全在浏览器本地运行的 PWA 原型，适合在 iPhone 17 的 Safari 中使用。

## 算法

- 先按"近黑"标准给每一行、每一列分类：像素 RGB 最大值不超过黑色阈值，并且该行/列中达到这个标准的像素比例不低于覆盖率阈值。
- 再找出**包含图像几何中心**的那一段连续"非近黑"内容，把它当作主体。四条边的裁剪量就是从这个中心段向上下左右量出去——凡是中心段之外没有连续内容的区域，一律裁掉。上、下、左、右四条边独立判断。
- 如果几何中心本身就落在黑区里（例如"界面工具条 + 长条黑边"把中心包住的截图，照片只占画面下半部分），说明"中心必在主体内"这个前提不成立，此时退化为取最长的一段连续内容，仍然能得到正确的主体。
- 只有当一条边需要裁掉的条带中，近黑行占比**严格过半**时才真正裁剪。不过半说明黑条是夹在画面中间的暗色物体（例如主体内部的黑色区域），为了它切掉外侧真正的内容不划算，此时保留原样交给手动微调；占比正好一半时按不裁处理（保守）。
- 单边最多裁掉轴长的 75%，保证主体至少还留下 1/4，作为兜底保护。
- 整幅近乎全黑时找不到主体，不做任何裁剪；过细的黑线由"最小黑边厚度"过滤掉。

这条路线不再依赖"图像中心一定落在主体内"这个假设。早期版本从图像中心向外扫描，遇到中心被黑区包住的截图时，扫描起点本身就落在黑区里，代码会把中心误判成黑边的内侧边缘，算出接近半个画布的裁剪量后被安全上限否定，最终四条边都不裁。

## 在 iPhone 上使用

1. 将此目录部署到任意支持 HTTPS 的静态网站，或在电脑上运行 `python3 -m http.server` 后用同一 Wi-Fi 访问。
2. 在 iPhone Safari 打开页面。
3. 点击“选择图片”，一次选择多张截图。
4. 所有图片会自动独立检测上、下、左、右四条边。
5. 默认检测参数已折叠；需要调整时点击“展开参数”。松开参数滑块或切换检测方向后自动应用，也可以点击“重新检测”。边界微调范围为 -5～30px，默认 0；负数仅对检测到黑边的方向向内多裁，正数保留边距。
6. 查看实际裁剪量与输出尺寸；必要时在对应图片里展开“手动微调四边”，修改数值并离开输入框后更新预览。重新应用检测参数会覆盖手动调整。
7. 点击页面顶部“保存全部”。
8. iPhone 系统分享面板中选择“存储图像”，一次保存全部处理后的图片。

网页不能绕过 iOS 权限直接写入照片库，因此最后一步仍由系统分享面板确认。若浏览器不支持多文件分享，可使用“逐张下载”。

首次打开后可以使用 Safari 的“添加到主屏幕”。应用会优先从本地缓存启动并在后台更新，因此后续打开更快；它不需要服务器，也不上传图片。

## 版本标注

页面右上角徽章显示形如 `Beta 2026.09.12` 的版本日期，用于区分设备上正在运行的是哪一版（PWA 有缓存，容易分辨不清）。

**每次改动页面内容时必须同步更新两处**，否则已安装到主屏幕的应用会继续使用旧缓存，徽章反而会误导：

1. `index.html` 里 `.badge` 的日期；
2. `sw.js` 里 `CACHE_NAME` 的版本号（递增，v11 → v12 …）——它一变，Service Worker 的 install 阶段会重新抓取全部资源。

## 图标

电脑书签、手机书签、手机主屏幕和网页预览统一使用深黑底、白色单字“裁”，不使用裁剪符号。SVG 字形已转为路径，所有 PNG 和 ICO 均来自同一字形，避免依赖设备字体。

图标生成（macOS，在项目根目录运行）：

```sh
clang -fno-modules -framework Foundation -framework CoreText -framework CoreGraphics -framework ImageIO scripts/generate-icons.m -o /tmp/luban-generate-icons
/tmp/luban-generate-icons
node --test tests/icons.test.mjs
```

图标文件名带有版本号。发布新图标时需要同时更新 HTML、manifest、Service Worker 的引用和缓存版本。浏览器已保存的旧书签图片可能需要重新收藏此项目页面后才会更新，不必清除其他网站的数据。
