# 截图智能裁剪

识别照片主体，裁掉多余留白、界面栏与角落标识。

[在线使用](https://kunlun7210.github.io/Cropper/) · [GitHub 仓库](https://github.com/kunlun7210/Cropper)

一个在浏览器本地运行的截图裁剪工具。面向 iPhone 的 Safari / 主屏幕使用，也可在电脑浏览器打开；无需登录，不上传图片，不覆盖原图。图标保持深黑底、白色单字“裁”，仓库名与网址保持 **Cropper**。

## 主要功能

- **自动裁剪**：独立检测四边黑留白及已确认的应用界面栏。
- **彩色 / 模糊背景**：识别看图界面中清晰照片的边界，裁掉外围渐变、模糊延伸、分类文字、缩略图和按钮。
- **底栏与标识**：轻量识别高德地图、艺龙完整文字 / logo、点赞爱心和相关看图底栏。
- **四角增强识别**：可选本地 OCR，扩展地图、旅行和平台品牌标识的识别。
- **精细调整与批量保存**：边界微调、每张图手动调四边、结果预览、带顺序编号的批量导出。
- **离线使用**：首次访问缓存完成后可离线打开；OCR 组件在启用并缓存完成后也可离线运行。

“裁剪标识”是裁掉标识所在的边缘条带，不是擦除水印或修复其覆盖的图像。

## 快速开始

1. 在 Safari 或电脑浏览器打开[在线页面](https://kunlun7210.github.io/Cropper/)。
2. 点击“选择图片”，选择一张或多张截图。支持 PNG、JPEG、WEBP。
3. 查看照片主体、实际裁剪量与输出尺寸。通常使用默认设置即可；需要时展开“检测参数”或单张图片的“手动微调四边”。
4. 点击“保存全部”。支持文件分享的 iPhone 会打开系统面板，再选择“存储图像”；也可使用“逐张下载”。

网页不能绕过 iOS 权限直接写入照片库。多文件分享能力取决于浏览器和系统；不支持时会逐张发起下载。PNG 输入导出为 PNG，JPEG / WEBP 输入导出为 JPEG。批量文件名带 `001、002、003…` 编号，方便保持顺序，但不能保证系统相册按文件名排序。

### 添加到 iPhone 主屏幕

在 Safari 中选择“分享 → 添加到主屏幕”。页面按 iPhone 17 / iPhone 17 Pro 的使用需求保留安全区域、手机布局和触控区域；实体设备的系统分享与实际耗时仍需设备验证。

新添加的主屏幕入口采用“截图智能裁剪”名称和“裁”字图标。已经保存的书签 / 主屏幕名称可能由系统或用户保留，不保证网页更新后自动改名；需要时手动更名，或从同一网址重新添加。无需更换网址。

## 检测参数

默认折叠；展开后可以调整。滑块左侧亮蓝、右侧暗灰，松开或切换选项后自动应用，也可点击“重新检测”。

参数标题与数值为 14px，说明为 13px；亮条厚度 4px、圆圈直径 18px，仍保留 44px 的滑块触控高度。手机单列、电脑双列；“界面栏”、底部标识与 OCR 选项统一排布，“恢复默认”位于标题旁。

| 参数 | 默认值 | 范围 | 用途 |
| --- | --- | --- | --- |
| 黑色阈值 | 42 | 5～100 | RGB 最大值不超过此值的像素算近黑色 |
| 横 / 竖线覆盖率 | 92% | 70%～100% | 一行 / 列需要有多少比例的像素接近黑色 |
| 最小黑边厚度 | 1.0% | 0.2%～8% | 过滤过细黑线，避免把偶然线条当成边框 |
| 边界微调 | 0 px | -5～30 px | 对已检测到边界的方向多裁或保留少量像素 |

边界微调的含义：

- `-1 px`：仅在检测到边界的方向额外向主体内裁 1 像素。
- `0 px`：按照检测边界裁剪。
- 正数：保留相应像素；没有检测到边界的方向仍为 0，不凭空裁剪。

其他选项：

- **检测方向**：默认四边全部开启，关闭某一方向就不自动裁该边。
- **界面栏**：默认开启，控制深色界面栏及已确认的彩色 / 模糊看图背景；关闭后仍保留基础黑边检测。
- **裁掉底部标识 / 点赞**：默认开启；关闭后停止相应标识与底栏识别，也不执行增强 OCR 裁剪。
- **四角增强识别（OCR）**：默认关闭，按需要开启。
- **恢复默认**：重置参数与选项，并重新检测当前图片。

单张图片的手动四边数值会即时更新预览；重新应用检测参数会覆盖手动调整。保存前会应用尚未提交的参数，并等待正在执行的增强识别，避免预览和输出使用不同设置。

## 角落标识如何识别

### 默认轻量识别

不需要下载模型。结合看图界面的顶部工具栏、照片边界、底部标识或空心爱心确认布局；识别高德地图和艺龙时包含旁边的完整 logo，也处理独立爱心。

多个要素同时出现时，以所有确认标识中更靠主体的边界为准，不因先发现点赞而忽略更靠上的标识。标识位于照片外时尽量保留完整照片；覆盖照片边缘时裁掉所在的窄条。

### 可选四角 OCR

启用后使用 **PP-OCRv6-small**，只扫描已经定位的照片主体四角，不扫描整张截图、外围导航或缩略图。每个角最多覆盖主体宽度的 38%、高度的 25%，并有固定像素上限；暗照片上的白色标识也会检查。

目前支持高德地图、百度地图、腾讯地图、美团、大众点评、携程、艺龙、同程、飞猪、去哪儿、淘宝，以及部分英文 / 域名别名。

文字、置信度、大小、贴边位置和邻近 logo 共同用于判断，不因照片中的长句包含品牌词就裁剪。四个角的多个确认标识会共同参与边界计算；原有完整 logo 模板优先，新增 OCR 裁剪限制在主体高度的 12% 内，并尊重方向开关和边界微调。

首次开启需联网下载约 **80 MB**，包括模型和本地运行组件；下载有 SHA-256 校验，缓存独立保存。关闭 OCR 不会删除已下载资源，也不影响默认轻量识别。识别任务串行执行；更换图片或参数后旧结果失效，晚到的结果不会覆盖手动调整。

## 识别原理与适用范围

本项目不是通用图像分割，也不会把“与照片颜色不同的区域”全部裁掉。几路检测有各自的确认条件：

1. **黑边与深色界面栏**：按行 / 列统计近黑覆盖率和贴边平坦深色区域，选择主体连续内容段；有厚度、纯度、对比度和单边裁剪比例等保护条件。全黑图片、过细黑线及缺少可靠证据的暗部保守处理。
2. **看图底栏与标识**：先确认界面布局，再定位照片及完整标识，多要素共同决定裁剪线。
3. **彩色 / 模糊背景**：确认状态栏与导航或应用胶囊，寻找整宽的上下照片边界；外侧须接近本张图的低纹理背景，内侧须明显更清晰。多个边界都通过时优先完整照片矩形，避免被建筑楼层、台阶等内部横线误导。最后在原始像素上细化边界。
4. **可选 OCR**：在已定位主体的四角补充品牌文字与邻近 logo 的证据，不替代默认检测。

旧黑边算法与已确认的旧看图布局保留，不为彩色背景放宽黑色阈值。缺少界面证据、照片不铺满宽度、边缘不清晰或全新布局时，可能需要手动微调。角落上的真实招牌也可能与水印相似，因此 OCR 保持可选；只有 logo、很小 / 很淡或位于主体中间的标识不保证识别。

## 隐私、缓存与更新

图片解码、识别、预览及导出均在浏览器本地完成，没有图片上传接口；原始文件不会被覆盖。联网请求用于加载网页与可选 OCR 组件，不需要账号或服务端推理。

首次访问需要联网。缓存完成后优先从本地启动，在后台检查更新；OCR 使用单独缓存，不会在默认启动时下载约 80 MB 的资源。发现新版本时，空闲页面自动刷新；正在处理图片时不强制刷新，避免丢失当前批次。

页面右上角显示版本与日期，例如 `v1.7.2 · 2026.10.07`。更新后仍见旧名称或旧版本时，可关闭页面 / 主屏幕应用后重新打开；不必清除其他网站的数据。

## 本地运行与开发

基础页面是静态网页，无需构建即可运行。在项目目录中执行：

```sh
python3 -m http.server 8788 --bind 127.0.0.1
```

在本机浏览器访问 `http://127.0.0.1:8788/`。此地址仅用于本机；iPhone 可直接使用公开 HTTPS 页面。

开发测试需 Node.js、npm，浏览器测试默认使用本机 Google Chrome：

```sh
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci
npm test
npm run test:browser
```

### 目录与扩展

| 文件 / 目录 | 职责 |
| --- | --- |
| `index.html`、`styles.css`、`manifest.json` | 页面、样式、安装信息及“裁”字图标引用 |
| `app.js` | 检测组合、边界细化、参数 / 手动调整、批量保存 |
| `viewer-detector.js`、`viewer-marks.js` | 看图界面、底栏、完整标识与爱心 |
| `frame-detector.js` | 彩色 / 模糊看图背景及清晰照片边界 |
| `corner-detector.js`、`corner-ocr.js`、`src/ocr-engine.mjs` | 品牌词表、四角规则、增强识别加载与引擎 |
| `brand-assets/`、`ocr/` | logo 来源 / 模板、模型 / 运行组件、许可和校验信息 |
| `sw.js`、`tests/` | 离线缓存、更新与回归验证 |

增加品牌时，优先在 `corner-detector.js` 集中维护名称 / 别名；需要 logo 模板时，应记录来源与处理信息，使用 `scripts/build-brand-logos.mjs` 生成模板，再按 [OCR 重建说明](ocr/NOTICE.md)更新版本化运行组件与校验清单。不是每遇到一个品牌都重写检测流程，但未知 logo 或全新布局仍可能需要补充证据。

处理新的看图背景样式时，扩展 `frame-detector.js` 的界面 / 边界确认并增加负例，不直接放宽全局黑色阈值。官方 logo 来源与处理记录见 [sources.json](brand-assets/sources.json) 和 [provenance.json](brand-assets/provenance.json)。

名称、文案或资源更新时，同步更新页面 / 包版本与 Service Worker 缓存版本，并核对实际 Pages 文件。保持 `start_url`、`scope` 和仓库网址不变；只清理本项目旧缓存，保留独立 OCR 缓存。模型 / 运行组件变更需使用新版本目录与缓存名，不能把不同组件混进旧缓存。

## 验证与已知限制

v1.7 检测方案已用 Chrome / WebKit 验证 69 张原始样本：原有 49 张保持各自引擎内的旧输出，新增 20 张彩色 / 模糊背景与手裁参考对照，并检查了真实 PNG 导出、方向 / 微调、JPEG 缩放、批量顺序、误裁负例及离线重开。可选 OCR 也验证了 69 张样本、11 品牌合成图 / 官方 logo、邻近 logo、多要素、延迟任务和缓存离线推理。

PNG 导出与实际裁剪画布像素一致；手裁 JPEG 参考有少量向内微调与压缩差异，不按文件字节比较。WebKit 对整图 / 局部绘制的色彩管理舍入可能相差 2/255。

WebKit 在旧图的三个人工变体上仍存在 v1.6 的既有漏检：小高德 logo 的 JPEG 放大、人工拼贴多标识、擦除点赞后仅剩作者底栏。同一解码剖面交给历史检测器可复现；测试写入 `limitations.json`，不算作通过，也不为掩盖它而降低全局门槛。

桌面 WebKit、手机尺寸布局不等于实体 Safari 验证。实体 iPhone 的系统分享、内存和实际耗时仍需设备测试；合成品牌图也不代表所有真实水印样式已经验证。

真实样本只从本地读取，不放入仓库或网站。样本根目录包含“新版测试图”“新版需要达到的效果”“旧版测试图”：

```sh
node tests/viewer-samples.cjs <样本根目录> <结果目录>
node tests/frame-overlays.cjs <新版测试图目录>
CROPPER_BROWSER=webkit npm run test:browser
CROPPER_BROWSER=webkit node tests/viewer-samples.cjs <样本根目录> <结果目录>
CROPPER_OCR_SAMPLES=1 npm run test:ocr
```

WebKit 测试需已安装对应 Playwright 引擎。单元测试不需要浏览器；网页 / 保存 / 缓存测试应以实际浏览器结果为准。
